## 修正单一标准片段的问题

每道题包含一到多个必需证据组；一个组允许多段已认可的等价原文。相同原文在其所属文档的多个位置出现也被计入。返回相邻片段共同完整覆盖指定跨度时，同样可计为支持，存在缺口则不计。

例如“一轮研究发现资料不足时怎么办？”同时接受工作流中的 need_more 分支和解释“根据具体缺口定向补证”的正文。本次四种方法均命中；原文混合检索排第 3，真实重排后排第 1，不再被旧单标签误判为失败。

这里仍只知道部分有效证据，不应把所有未标片段直接视作错误。因此使用 **已标有效证据 Hit@5**，不再把单个标准跨度命中称为完整语义 Recall。其他合理但未列出的证据仍可能产生假阴性，后续需要独立标注审查。

- **Hit@5**：前五个片段支持至少一个已标必需证据组。
- **MRR@5**：前五名中首次支持某个证据组的最早排名倒数；跨片段支持按完整覆盖时的排名计算。
- **证据组覆盖率**：所有必需事实中被支持的比例，用于多来源任务。
- **全部证据组命中率**：一道多来源题是否把所需事实全部找齐。

## 模型与实验协议

真实 Embedding：`sentence-transformers:intfloat/multilingual-e5-small`，`degraded=false`。

真实 CrossEncoder：`cross-encoder/mmarco-mMiniLMv2-L12-H384-v1`，实际加载权重并预测。每次在 20 个候选内重排，最终取 Top5；模型出错则此次评测失败，不把降级结果当作重排结果。

四个检索变体使用同一冻结语料、切片逻辑和评分标签；多来源诊断固定原文索引＋同一个重排模型。标签只进入评分器，不用于构造向量、检索文本、模型输入或来源过滤。历史题使用公开指定的“旧快照入库时点”过滤，验证的是抓取／导入时间，不是政策法律生效时间。

## 真实项目文档：72 条

| 方法 | 已标有效证据 Hit@5 | MRR@5 | 平均耗时 | P95耗时 |
|---|---:|---:|---:|---:|
| 原文混合检索 | 45.8% | 0.305 | 63.6 ms | 70.9 ms |
| 原文混合＋真实重排 | 68.1% | 0.615 | 191.9 ms | 218.1 ms |
| 背景索引混合检索 | 45.8% | 0.328 | 62.9 ms | 66.7 ms |
| 背景混合＋真实重排 | 66.7% | 0.601 | 187.5 ms | 209.2 ms |

原文混合检索命中 **33/72**；加真实重排后 **49/72**。逐题配对：16 条从未命中变命中，0 条发生反向变化；排序仍可能个别下降，并非每条题都改善。尚有 **23/72** 未命中已标证据，不应称为已解决通用文档问答。

本轮问题更多、语料更大、标签与指标定义也已修正，不能拿 v2 的 83.3% 和本轮 45.8% 直接比较为算法退化。四个变体之间的横向比较才使用同一协议。

## 合成诊断：32 条

| 方法 | 已标有效证据 Hit@5 | MRR@5 | 平均耗时 | P95耗时 |
|---|---:|---:|---:|---:|
| 原文混合检索 | 78.1% | 0.549 | 63.1 ms | 67.3 ms |
| 原文混合＋真实重排 | 100.0% | 1.000 | 161.3 ms | 221.5 ms |
| 背景索引混合检索 | 100.0% | 0.854 | 63.4 ms | 66.2 ms |
| 背景混合＋真实重排 | 100.0% | 1.000 | 156.9 ms | 216.3 ms |

背景索引和重排在这组题上更容易发挥作用；这些资料刻意存在相近格式、不同实体／年份／单位，且问题共用模板，所以不能将 100% 外推为真实业务准确率。

## 多来源 Worker 前置上下文：8 条

固定最多 5 个片段、6000 个序列化字符、每来源最多 2 个片段。两组均用原文索引＋真实重排，只改变查询组织方式。

| 方法 | 平均必需证据组覆盖率 | 全部证据找齐 | 平均资料包字符 | 平均耗时 |
|---|---:|---:|---:|---:|
| 拼成一个长查询 | 77.1% | 62.5%（5/8） | 3158 | 286.3 ms |
| 分子问题检索并保留各自候选 | 87.5% | 87.5%（7/8） | 3401 | 617.3 ms |

找齐所需证据的任务增加了，但额外查询使本机平均耗时从约 286ms 增至 617ms。这里只验证给 Worker 的输入资料，不包含真实 LLM 策略好坏或最终报告准确率。

## 无答案诊断：12 条

四个变体均在 **12/12** 无答案题上返回了候选。候选可能是相近的历史资料或安全说明，返回候选不等于模型已生成错误答案；但也说明检索层目前没有通过这些题证明“无答案时自动筛空／拒答”的能力。Worker 的后续资料审查仍然必要，不能因为 RAG 有命中就当作已有答案。

## 测试与复现

本轮新增评分器和冻结数据校验测试，与 RAG 流程测试合跑，**28 项通过**。覆盖多有效片段、相邻片段覆盖、缺口不算支持、多事实题部分完成、错误来源、Top5 截断、无答案不计伪高分、标签哈希变更拒绝等。此前生产流程回归记录见 v2 报告；本次没有修改生产 RAG 实现。

```bash
HF_HUB_OFFLINE=1 python -m evaluation.knowledge_rag.run_v3
python -m pytest tests/test_knowledge_benchmark.py tests/test_knowledge_rag.py -q
```

预先缓存 E5 与重排模型；去掉离线环境变量可正常加载模型。此运行索引及评测总耗时约 55.3 秒，逐次查询延迟不含模型初次加载；单机顺序实验、样本有限，P95 仅作诊断。未测真实 API Token、线上费用或最终报告质量。

`build_v3` 用于显式重新冻结题集；一般复现直接运行 `run_v3`，不要先重建数据。新版本题集应单独留存，避免用覆盖旧文件的方式掩盖改动。
